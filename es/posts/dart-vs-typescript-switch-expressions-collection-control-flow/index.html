¿Te falta Dart? Cuando TypeScript se siente como el desierto Link to heading

Recientemente, me topé con una conversación en Twitter que resonó profundamente con algunos de mis propios “dolores” como desarrollador. Se trataba de la frustración de trabajar en TypeScript y extrañar ciertas características de sintaxis que hacen que la vida sea mucho más dulce en Dart.

Si alguna vez te has sentido como si estuvieras “muriendo de sed” buscando una forma elegante de manejar condicionales o construir listas en TypeScript, no estás solo. Hoy exploraremos dos de esas características que hacen que Dart se sienta tan ergonómico: las Expresiones Switch y el Control de Flujo en Colecciones.

1. Expresiones Switch: Cuando un switch devuelve un valor Link to heading

Imagina que quieres asignar un valor a una variable basándote en diferentes condiciones. En TypeScript (o JavaScript), un switch es una declaración, no una expresión. Esto significa que no puedes usarlo directamente para devolver un valor. Tienes que declarar una variable, y luego asignarle un valor dentro de cada case.

// Ejemplo en TypeScript (sin expresiones switch)
function obtenerEstadoDelTrafico(colorSemaforo: string): string {
  let estado: string; // Tienes que declarar la variable aquí
  switch (colorSemaforo) {
    case 'rojo':
      estado = 'Detener';
      break;
    case 'amarillo':
      estado = 'Precaución';
      break;
    case 'verde':
      estado = 'Avanzar';
      break;
    default:
      estado = 'Desconocido';
      break;
  }
  return estado;
}

console.log(obtenerEstadoDelTrafico('rojo')); // Salida: Detener

Es funcional, sí. ¿Pero podríamos hacerlo más conciso? ¡Absolutamente!

La elegancia en Dart:

Dart, al igual que otros lenguajes modernos, permite que un switch sea una expresión que directamente produce un valor. Esto elimina la necesidad de break y de la asignación repetida. Es mucho más limpio.

// Ejemplo en Dart (con expresiones switch)
String obtenerEstadoDelTrafico(String colorSemaforo) {
  // El switch directamente devuelve el valor
  return switch (colorSemaforo) {
    'rojo' => 'Detener',
    'amarillo' => 'Precaución',
    'verde' => 'Avanzar',
    _ => 'Desconocido', // El guion bajo (_) actúa como el default
  };
}

void main() {
  print(obtenerEstadoDelTrafico('rojo')); // Salida: Detener
}

¿Ves la diferencia? El código de Dart es más directo y expresivo.

2. Control de Flujo en Colecciones: Construyendo listas de forma inteligente Link to heading

Esta es, quizás, la característica que más se extraña. ¿Alguna vez quisiste añadir condicionalmente un elemento a una lista o iterar sobre algo para construir otra lista, todo dentro de la propia declaración de la lista?

El dilema en TypeScript:

En TypeScript, si quieres añadir elementos condicionalmente a un array, normalmente tienes que recurrir a la manipulación del array después de su creación, o usar el operador spread (...) de forma algo más verbosa.

// Ejemplo en TypeScript (sin control de flujo en colecciones)
interface Usuario {
  id: number;
  nombre: string;
  esAdmin: boolean;
}

const usuarioActual: Usuario = { id: 1, nombre: 'Alice', esAdmin: true };
const mostrarBotonAdmin: boolean = usuarioActual.esAdmin;

let opcionesMenu: string[] = [
  'Inicio',
  'Perfil',
];

// Opcion 1: push condicional
if (mostrarBotonAdmin) {
  opcionesMenu.push('Panel de Administración');
}

// Opcion 2: spread operator (un poco mejor, pero aún no tan integrado)
const opcionesMenuMejorado: string[] = [
  'Inicio',
  'Perfil',
  ...(mostrarBotonAdmin ? ['Panel de Administración'] : []), // Añade un array vacío si la condición es falsa
  'Cerrar Sesión'
];

console.log(opcionesMenu);         // Salida: ['Inicio', 'Perfil', 'Panel de Administración']
console.log(opcionesMenuMejorado); // Salida: ['Inicio', 'Perfil', 'Panel de Administración', 'Cerrar Sesión']

Ambas opciones funcionan, pero la primera rompe la inmutabilidad inicial de la lista, y la segunda introduce un patrón un poco extraño con arrays vacíos para manejar la condicionalidad dentro de la declaración.

La magia en Dart:

En Dart, puedes incrustar directamente sentencias if y for dentro de la sintaxis de las colecciones (listas, sets, mapas). Esto hace que la construcción de estructuras de datos complejas sea increíblemente legible y concisa.

// Ejemplo en Dart (con control de flujo en colecciones)
class Usuario {
  final int id;
  final String nombre;
  final bool esAdmin;

  Usuario({required this.id, required this.nombre, required this.esAdmin});
}

void main() {
  final Usuario usuarioActual = Usuario(id: 1, nombre: 'Alice', esAdmin: true);
  final bool mostrarBotonAdmin = usuarioActual.esAdmin;

  final List<String> opcionesMenu = [
    'Inicio',
    'Perfil',
    if (mostrarBotonAdmin) 'Panel de Administración', // ¡Aquí está la magia!
    'Configuración',
    for (int i = 1; i <= 3; i++) 'Opción ${i}', // También puedes usar for loops
    'Cerrar Sesión',
  ];

  print(opcionesMenu);
  // Salida: [Inicio, Perfil, Panel de Administración, Configuración, Opción 1, Opción 2, Opción 3, Cerrar Sesión]
}

¡Es una delicia! El código fluye de forma natural, y la intención de añadir elementos condicionalmente o de forma iterativa es inmediatamente clara.

¿Qué aprendemos de esto? Link to heading

No se trata de decir que un lenguaje es “mejor” que otro en todos los aspectos. TypeScript y JavaScript son herramientas poderosas y omnipresentes con sus propias fortalezas. Sin embargo, estas pequeñas “mejoras” de calidad de vida en la sintaxis de Dart demuestran cómo un lenguaje puede evolucionar para hacer el código más declarativo y menos imperativo, lo que a menudo resulta en menos errores y una mayor legibilidad.

Para aquellos de nosotros que saltamos entre Dart y TypeScript, estas son las características que nos hacen decir: “Ah, si tan solo lo tuviéramos en TS…”
