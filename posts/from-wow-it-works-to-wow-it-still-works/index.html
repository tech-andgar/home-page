From "Wow It Works!" to "Wow It Still Works"

July 23, 2026 8-minute read

From “Wow It Works!” to “Wow It Still Works” Link to heading

Making vibecoded apps production-worthy in five steps.

Vibecoding — term popularized by Andrej Karpathy (Feb 2025). Word of the Year 2025 — Collins Dictionary · Merriam-Webster trend.

There’s a dangerous moment in every AI-assisted project: the moment the demo works perfectly on localhost:8000 and the team declares “we’re done.” The button changes color. The data loads. Business sees a finished product. Engineering sees the beginning of the real work.

This guide is the survival manual for what comes after the demo.

The Problem: Local Success ≠ Architectural Resilience Link to heading

Two real stories from the field:

The Business Paradox. An Analytics Lead walks into the room: “Don’t worry about timelines, guys. We’ve already got it ready. We put it together in two hours with an AI assistant, we just need to deploy it.” For business, the backend and infrastructure are perceived as a mere copy-and-paste formality.

The 5-Day Pitch. Built in 5 days with Claude, looked incredible in the demo. Then a real load test: 10 concurrent users brought it down. The database was being opened and closed on every request. No pagination. No error boundaries. The happy path was perfect. Everything else was not.

The Uncomfortable Data Link to heading

  • +24% perceived speed by the developer
  • -19% real measured speed — complex and familiar repos (METR, 2025)1

Amdahl’s Law explains it: when code generation approaches zero cost, the bottleneck shifts entirely to human review. More AI output = more review bottleneck = potentially slower overall if you don’t restructure the workflow.

And the structural debt is real: 4×–8× more code duplication in AI-assisted repos (GitClear, 2024)2. Refactoring fell from 25% to under 10% of all changes between 2021 and 2024. The result: “haunted codebases” — software that works, but the team doesn’t fully understand.

The Security Reality Link to heading

Three converging signals from peer-reviewed research:

  • 41% more prone to introducing vulnerabilities without manual validation (Stanford/UIUC)3
  • 45% of generation tasks introduce at least one known vulnerability4
  • +37% critical vulnerabilities after 5 iterations of conversational refinement5

The seven recurring vulnerability categories: hardcoded secrets, missing input validation, insecure authentication, broken access control (IDOR), SQL injection, outdated dependencies, and exposed environment variables.

The Demarcation Line Link to heading

The problem isn’t the tool. The problem is skipping the review.

AI-Assisted DevelopmentPure Vibecoding
Supervised pair-programmerAcceptance without review
Review the diff, migrations, dependency tree“Click to see if it works”
Human owns the contractHuman absent from the output

80% of Anthropic’s production code is already written by Claude. One-third of bugs responsible for historical outages were caught by their automated reviewer in CI/CD — before production. The role shift is real: you are no longer an author of syntax. You are a curator, auditor, and high-fidelity validator.

The Survival Manual: Five Steps Link to heading

Step 0 · Threat Model Link to heading

Hardening without a threat model is checklist security. Before touching code, spend 10–15 minutes with STRIDE on your data flow:

  • Spoofing — who impersonates a user or service?
  • Tampering — data modified in transit?
  • Repudiation — actions denied without audit?
  • Info Disclosure — leaks via logs, errors, side channels?
  • Denial of Service — unbounded ops exhausting resources?
  • Elevation — user reaching admin functions?

Without this, you don’t know what you’re defending against.

Step 1 · Sanitation and Secrets Link to heading

The most urgent step — and the one most projects skip entirely.

  1. Purge — scan the entire Git history with TruffleHog. Run git filter-repo or BFG to rewrite it. Rotate all compromised credentials. Configure automated rotation: short-lived tokens, OIDC federation.
  2. Isolate — move configs to Secret Manager (Vault, AWS Secrets Manager, Cloud Secret Manager). Inject at process init with workload identity. No long-lived service account keys.
  3. Scan — automatic gate: native container vulnerability scanning prevents an image with critical CVEs from being stored or deployed.

Step 2 · Stateless Infrastructure Link to heading

AI-generated prototypes couple the database to the development server. This destroys horizontal scaling. Serverless containers (Cloud Run, AWS Fargate, Azure Container Apps) enforce a stateless paradigm:

  • Isolates the container from memory leaks or poorly optimized threads
  • Scales from zero to hundreds of instances on real traffic
  • Ephemeral environments for testing without touching production
  • Concurrency limits as cost gates — AI-generated unbounded loops hit the ceiling, not a $4,000 bill

Enforce with Infrastructure-as-Code (Terraform/Pulumi/CDK). No manual config drift. 12-factor compliance: no filesystem writes, externalized config, process disposability.

Step 3 · Data Hardening Link to heading

Under massive traffic, the database collapses not from capacity, but from poor access patterns.

  1. Connection Pooling — reuse channels with explicit pool size limits. AI-generated code often leaves pools unlimited. One config line fixes this.
  2. Cursor-Based Pagination — prefer cursor/keyset over offset for scale. Strict limit on every read endpoint to prevent DoS from RAM exhaustion.
  3. Row-Level Security — data isolation guaranteed by the persistence engine, not a failure-prone application script. Tackles IDOR/broken access control.
  4. Encryption at Rest — Customer-Managed Encryption Keys (CMEK) for sensitive data. Classify tiers: PII, financial, public. Key rotation on schedule.

Step 4 · Unified QA Link to heading

Passing an isolated functional test is not enough. Under real concurrency, the experience degrades.

  • K6 — massive stress ramp against services and database in the cloud
  • Playwright — simulates real users in real browsers, simultaneously
  • OpenTelemetry — structured logs + distributed tracing + metrics (the three observability pillars)

Define SLOs: latency p95 < 200ms, error rate < 0.1%. Error budgets trigger architectural review — not optional escalation.

Step 5 · Perimeter Governance Link to heading

Static analysis reviews code text. A DAST scanner (OWASP ZAP, Nuclei, Web Security Scanner) attacks the live system. It detects:

  • Code injection and XSS at runtime
  • Misconfigured security headers (CSP, HSTS, X-Frame-Options)
  • Accidental exposure of development server signatures

On ephemeral URLs in the serverless environment: if it detects a policy deviation → blocks container promotion.

Runtime defense: WAF + rate limiting in production. mTLS between services. Egress filtering — AI-generated code must not call arbitrary external endpoints.

The DevSecOps Gate Checklist Link to heading

PhaseOwnerTimeKey Actions
1 · Before GeneratingTech Lead5–10 minSTRIDE threat model, define failure modes, DB schema + API contract, “no silent failures” constraint
2 · After GeneratingPeer Reviewer15–30 minScan for hardcoded secrets, SAST (Semgrep p/owasp-top-ten), verify auth on every new route, lockfile integrity check
3 · Before DeployingCI Pipeline10–20 minIntegration and regression, smoke tests (5 critical paths), SCA + lockfile hash, architecture fitness check (no cyclic deps)
4 · After DeployingOn-call + PM30+ minStructured logs + distributed tracing, SBOM diff (CycloneDX/SPDX) per release, SLO error budget check, anomaly alerts (MTTD < 5 min)

Each gate must pass before advancing.

The Methodology: Spec-Driven Development (SDD) Link to heading

Gates are only sustainable when backed by specs. SDD separates the what (business) from the how (syntax) — specs as non-negotiable contracts.

Three Layers Link to heading

  1. Constitution — purpose, boundaries, and architectural decisions (mission.md, tech-stack.md, roadmap.md, decisions/)
  2. Specifications — one folder per feature (requirements.md, plan.md, validation.md)
  3. P-I-V Loop — Plan (critical reflection agent reviews the plan) → Implement (spec as system prompt) → Validate (tests vs. contracts)

Supported natively by Kiro (AWS), Spec Kit (GitHub), and Tessl.

Brain and Muscles Link to heading

The AI Digital Engineer pattern operates in two strict layers:

The Brain (Claude, GPT-4, etc.) — reasons, debugs, and recovers. Structured in Markdown — without spending tokens remembering policies on every commit.

The Muscles (shell hooks) — deterministic barriers in milliseconds, at zero token cost:

2
3
4

check-design-canvas.sh   # missing specs → abort
check-unit-tests.sh      # fail → block commit
check-api-contract.sh    # OpenAPI drift → reject
verify-completion.sh     # validate CI gates

The agent cannot skip them. When check-unit-tests.sh blocks the commit, the agent gets an error and must fix the tests. It cannot argue its way past a bash script.

Traceability Link to heading

Every commit carries full attribution via a prepare-commit-msg hook:

Without an audit trail, a vulnerability at 3 AM turns a 20-minute triage into days reconstructing who wrote the code and how many services share the same AI failure.

The Maturity Model Link to heading

LevelNameState
0ChaoticPure vibecoding. No review, no specs. Breach imminent.
1ReactiveSteps 1–2 partial. .gitignore + secrets scan. High exposure.
2DefinedSteps 1–3 + SDD constitution. Controlled risk.
3ManagedSteps 0–5 + KPIs tracked (MTTD, gate pass rate, spec coverage). Measurable.
4OptimizedAutomated remediation, error budgets, architectural fitness functions. Resilient.

Start at Level 1 — get to Level 2 in one sprint. Each level unlocks the next.

The Five Things to Remember Link to heading

  1. Vibecoding ≠ shipping. Local success is not architectural resilience. The demo is not the product.
  2. Review > Generate. The bottleneck moved. You’re a curator now, not an author.
  3. Gates are non-negotiable. Secrets, stateless infra, data hardening, QA, perimeter scan — skip one, pay later.
  4. Specs before prompts. Define contracts in Markdown, then let the agent implement against them.
  5. Automate discipline. Hooks + CI gates = barriers agents can’t skip. Zero tokens, unbreakable.

Fund the investment — 5 steps ≈ 1 sprint. A breach ≈ $4.4M (IBM, 2025). Budget it or accept the risk explicitly.
