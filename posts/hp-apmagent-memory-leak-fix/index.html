Fix: memory and Mach port leak in HP APMAgent (macOS)

September 15, 2026 4-minute read
Local-Infrastructure
Macos • Sysadmin • Hp • Launchd • Troubleshooting

Context Link to heading

Activity Monitor showed kernel_task at ~27 GB and APMAgent at ~10 GB of reported memory, along with 219+ open Mach ports for APMAgent.

Diagnosis Link to heading

  • High kernel_task memory is normal: it’s macOS’s kernel mechanism for thermal/memory-pressure management, not a real process consuming that RAM. Not actionable.
  • APMAgent (original PID, 10+ days of uptime) actually had only ~120 MB of RSS; the inflated number in Activity Monitor comes from reported virtual/shared memory, not physical usage.
  • The real concerning data point: 219 Mach ports accumulated and 10 days 11 hours of uptime without a restart — consistent with a slow leak of internal (IPC) resources, not a network leak.
  • The process belongs to HP Insights (formerly HP TechPulse / HPDaaS), an enterprise device management agent:
    • Binary: /usr/local/share/APMAgent/APMAgent
    • LaunchDaemon: /Library/LaunchDaemons/com.hp.APMAgent.plist
    • Bundle ID: com.hp.DaasClient.macOS.APMAgent
    • Team ID: 6HB5Y2QTA3

Root causes identified in the agent’s own log Link to heading

In /var/log/APMAgent/agent.log (15 MB accumulated):

  1. It scans every app in /Applications with system_profiler on each cycle, generating repeated errors for every app missing Contents/version.plist (most of the installed ones).
  2. It calls /usr/local/bin/protectctl, which doesn’t exist on this system — fails on every run.
  3. CoreData warning about an insecure/nil NSValueTransformer in its data model (PageLoadErrorDataClassEntity), a typical sign of a serialization bug.
  4. It uploads telemetry via the AWS SDK (aws_sdk_*.log) fairly frequently.

Source configuration (com.hp.APMAgent.plist) Link to heading

<key>ThrottleInterval</key>
<integer>10800</integer>

launchd only relaunches the process if it exits successfully or crashes. If the process stays alive (even while slowly accumulating resources), it never restarts on its own — there are no effective ResourceLimits on modern macOS, nor any periodic refresh cycle.

Mitigation applied Link to heading

Aggressively editing HP’s plist was ruled out because:

  • It can be overwritten by any update pushed through MDM (Intune/Jamf).
  • It can trigger integrity alerts in corporate compliance tooling.
  • ResidentSetSize under SoftResourceLimits/HardResourceLimits is deprecated on macOS 10.15+ and generally ignored.

1. Immediate manual restart Link to heading

1

sudo launchctl kickstart -k system/com.hp.APMAgent

Restarts the process cleanly without affecting anything else and without requiring a reboot.

2. Targeted configuration tweak (with backup) Link to heading

1
2
3
4

sudo cp /Library/LaunchDaemons/com.hp.APMAgent.plist /Library/LaunchDaemons/com.hp.APMAgent.plist.bak
sudo plutil -replace ThrottleInterval -integer 3600 /Library/LaunchDaemons/com.hp.APMAgent.plist
sudo launchctl bootout system/com.hp.APMAgent
sudo launchctl bootstrap system /Library/LaunchDaemons/com.hp.APMAgent.plist

Lowers ThrottleInterval from 3h to 1h, so the agent recovers faster after an actual crash. The original plist is preserved as com.hp.APMAgent.plist.bak.

3. Dedicated periodic-restart LaunchDaemon (non-invasive) Link to heading

Rather than touching the vendor software further, a separate LaunchDaemon was created to restart APMAgent every 24 hours, preventing it from accumulating memory/ports over multiple days again:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.andres.apmagent-restart</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/bin/launchctl</string>
        <string>kickstart</string>
        <string>-k</string>
        <string>system/com.hp.APMAgent</string>
    </array>
    <key>StartInterval</key>
    <integer>86400</integer>
    <key>RunAtLoad</key>
    <false/>
    <key>StandardOutPath</key>
    <string>/tmp/apmagent-restart.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/apmagent-restart.log</string>
</dict>
</plist>

Verification Link to heading

1
2

ps -o pid,ppid,%mem,rss,etime,command -p $(pgrep -x APMAgent)
sudo launchctl print system/com.andres.apmagent-restart

Result after the fix: APMAgent running with ~90 MB RSS, uptime reset, and the scheduled restart job active (run interval = 86400 seconds).

Notes for IT / follow-up Link to heading

  • This is a bug/poor practice in HP’s own software (lack of resource cleanup + no periodic self-restart), not a user misconfiguration.
  • No independently downloadable public update was found; HP Insights is normally updated via Jamf Pro / corporate MDM (on this machine, managed by Intune / Company Portal).
  • Recommendation: report the Mach port accumulation behavior in com.hp.APMAgent to IT/helpdesk so they can check whether a newer version is deployable through their management console.
