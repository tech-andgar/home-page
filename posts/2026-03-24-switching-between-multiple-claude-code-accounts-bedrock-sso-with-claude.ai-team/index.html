Switching Between Multiple Claude Code Accounts (Bedrock SSO + Claude.ai Team)

March 24, 2026 3-minute read
Devtools • Ai
Claude-Code • Aws-Bedrock • Sso • Developer-Tools

Problem Link to heading

Claude Code stores its auth provider in ~/.claude/settings.json. If your machine is configured for AWS Bedrock SSO (e.g. via corporate setup), it overrides everything — including shell env vars and VSCode workspace settings. Logging out and back in doesn’t help because Bedrock reconnects automatically via AWS credentials.

Root Cause Link to heading

~/.claude/settings.json has an env block that injects env vars at the Claude process level, before your shell can override them:

1
2
3
4
5
6
7

{
  "env": {
    "CLAUDE_CODE_USE_BEDROCK": "1",
    "ANTHROPIC_MODEL": "global.anthropic.claude-sonnet-4-6",
    ...
  }
}

This is set by corporate/IT Bedrock configuration and cannot be overridden by terminal aliases or VSCode workspace settings alone.

Solution: Shell Functions that Patch settings.json Link to heading

Rename the functions to match your context (e.g. claude-company / claude-client). Add these to ~/.zshrc:

# Claude account toggle
export CLAUDE_CODE_USE_BEDROCK=0  # default: non-Bedrock

# Switch to AWS Bedrock (e.g. your employer's SSO account)
claude-company() {
  python3 -c "
import json
with open('$HOME/.claude/settings.json', 'r') as f: d = json.load(f)
d.setdefault('env', {}).update({
  'CLAUDE_CODE_USE_BEDROCK': '1',
  'ANTHROPIC_MODEL': 'global.anthropic.claude-sonnet-4-6',
  'ANTHROPIC_DEFAULT_HAIKU_MODEL': 'global.anthropic.claude-haiku-4-5-20251001-v1:0',
  'ANTHROPIC_DEFAULT_SONNET_MODEL': 'global.anthropic.claude-sonnet-4-6',
  'ANTHROPIC_DEFAULT_OPUS_MODEL': 'global.anthropic.claude-opus-4-6-v1',
  'CLAUDE_CODE_SUBAGENT_MODEL': 'global.anthropic.claude-haiku-4-5-20251001-v1:0',
  'AWS_REGION': 'us-east-1',       # adjust to your region
  'AWS_PROFILE': 'default'          # adjust to your AWS profile
})
with open('$HOME/.claude/settings.json', 'w') as f: json.dump(d, f, indent=2)
"
  claude auth logout 2>/dev/null
  echo "→ AWS Bedrock (company)"
}

# Switch to Claude.ai Team (e.g. your client's account)
claude-client() {
  python3 -c "
import json
with open('$HOME/.claude/settings.json', 'r') as f: d = json.load(f)
for k in ['CLAUDE_CODE_USE_BEDROCK','ANTHROPIC_MODEL','ANTHROPIC_DEFAULT_HAIKU_MODEL','ANTHROPIC_DEFAULT_SONNET_MODEL','ANTHROPIC_DEFAULT_OPUS_MODEL','CLAUDE_CODE_SUBAGENT_MODEL','AWS_REGION','AWS_PROFILE']:
  d['env'].pop(k, None)
with open('$HOME/.claude/settings.json', 'w') as f: json.dump(d, f, indent=2)
"
  claude auth logout 2>/dev/null
  echo "→ Claude.ai Team (client)"
  claude auth login
}

Reload: source ~/.zshrc

Usage Link to heading

1
2
3

claude-company     # Switch to AWS Bedrock SSO (employer)
claude-client      # Switch to Claude.ai Team (opens browser login)
claude auth status # Verify active account

Expected output after claude auth status:

Bedrock:

1

{ "authMethod": "third_party", "apiProvider": "bedrock" }

Claude.ai Team:

1

{ "authMethod": "claude.ai", "apiProvider": "firstParty", "email": "you@company.com" }

Key Lessons Link to heading

What we triedWhy it didn’t work
Shell unset CLAUDE_CODE_USE_BEDROCKsettings.json re-injects it after shell loads
VSCode terminal.integrated.env.osxExtension process env wins over terminal env
VSCode workspace claudeCode.environmentVariablesDoesn’t override the global settings.json env block
Project-level ~/.claude/projects/.../settings.jsonProject env doesn’t override global env
claude auth logoutBedrock reconnects via AWS credentials — no oauth needed

The only thing that works: directly patch ~/.claude/settings.json.
