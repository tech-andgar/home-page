Missing Dart? When TypeScript Feels Like a Desert

October 11, 2025 5-minute read

Missing Dart? When TypeScript Feels Like a Desert Link to heading

I recently stumbled upon a Twitter conversation that deeply resonated with some of my own “pains” as a developer. It was about the frustration of working in TypeScript and missing certain syntax features that make life so much sweeter in Dart.

If you’ve ever felt like you were “dying of thirst” looking for an elegant way to handle conditionals or build lists in TypeScript, you are not alone. Today, we’ll explore two of those features that make Dart feel so ergonomic: Switch Expressions and Collection Control Flow.

1. Switch Expressions: When a switch Returns a Value Link to heading

Imagine you want to assign a value to a variable based on different conditions. In TypeScript (or JavaScript), a switch is a statement, not an expression. This means you cannot use it directly to return a value. You have to declare a variable and then assign a value to it within each case.

// TypeScript Example (without switch expressions)
function getTrafficStatus(trafficLightColor: string): string {
  let status: string; // You must declare the variable here
  switch (trafficLightColor) {
    case 'red':
      status = 'Stop';
      break;
    case 'yellow':
      status = 'Caution';
      break;
    case 'green':
      status = 'Go';
      break;
    default:
      status = 'Unknown';
      break;
  }
  return status;
}

console.log(getTrafficStatus('red')); // Output: Stop

It’s functional, yes. But could it be more concise? Absolutely!

The Elegance in Dart:

Dart, like other modern languages, allows a switch to be an expression that directly produces a value. This eliminates the need for break statements and repetitive assignment. It’s significantly cleaner.

// Dart Example (with switch expressions)
String getTrafficStatus(String trafficLightColor) {
  // The switch directly returns the value
  return switch (trafficLightColor) {
    'red' => 'Stop',
    'yellow' => 'Caution',
    'green' => 'Go',
    _ => 'Unknown', // The underscore (_) acts as the default case
  };
}

void main() {
  print(getTrafficStatus('red')); // Output: Stop
}

Do you see the difference? The Dart code is more direct and expressive.

2. Collection Control Flow: Smart List Building Link to heading

This is arguably the feature that is missed the most. Have you ever wanted to conditionally add an element to a list or iterate over something to build a new list, all inside the list’s declaration?

The Dilemma in TypeScript:

In TypeScript, if you want to conditionally add elements to an array, you typically have to resort to manipulating the array after its creation, or use the spread operator (...) in a somewhat verbose way.

// TypeScript Example (without collection control flow)
interface User {
  id: number;
  name: string;
  isAdmin: boolean;
}

const currentUser: User = { id: 1, name: 'Alice', isAdmin: true };
const showAdminButton: boolean = currentUser.isAdmin;

let menuOptions: string[] = [
  'Home',
  'Profile',
];

// Option 1: Conditional push
if (showAdminButton) {
  menuOptions.push('Admin Panel');
}

// Option 2: Spread operator (a bit better, but still not fully integrated)
const enhancedMenuOptions: string[] = [
  'Home',
  'Profile',
  ...(showAdminButton ? ['Admin Panel'] : []), // Add an empty array if the condition is false
  'Logout'
];

console.log(menuOptions);           // Output: ['Home', 'Profile', 'Admin Panel']
console.log(enhancedMenuOptions);   // Output: ['Home', 'Profile', 'Admin Panel', 'Logout']

Both options work, but the first breaks the initial immutability of the list, and the second introduces a somewhat awkward pattern with empty arrays to handle conditionality within the declaration.

The Magic in Dart:

In Dart, you can directly embed if and for statements within collection syntax (lists, sets, maps). This makes building complex data structures incredibly readable and concise.

// Dart Example (with collection control flow)
class User {
  final int id;
  final String name;
  final bool isAdmin;

  User({required this.id, required this.name, required this.isAdmin});
}

void main() {
  final User currentUser = User(id: 1, name: 'Alice', isAdmin: true);
  final bool showAdminButton = currentUser.isAdmin;

  final List<String> menuOptions = [
    'Home',
    'Profile',
    if (showAdminButton) 'Admin Panel', // Here is the magic!
    'Settings',
    for (int i = 1; i <= 3; i++) 'Option ${i}', // You can also use for loops
    'Logout',
  ];

  print(menuOptions);
  // Output: [Home, Profile, Admin Panel, Settings, Option 1, Option 2, Option 3, Logout]
}

It’s a delight! The code flows naturally, and the intent to conditionally or iteratively add elements is immediately clear.

What Do We Learn from This? Link to heading

This isn’t about declaring one language “better” than the other across all metrics. TypeScript and JavaScript are powerful, ubiquitous tools with their own strengths. However, these small “quality-of-life” improvements in Dart’s syntax show how a language can evolve to make code more declarative and less imperative, often leading to fewer bugs and greater readability.

For those of us who jump between Dart and TypeScript, these are the features that make us say, “Oh, if only we had that in TS…”
